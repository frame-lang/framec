# RFC-0046 — `@@:self` as the portable, blessed self-reference

- **Status:** Draft
- **Author:** Mark Truluck <mark.truluck@cogiton.com>
- **Created:** 2026-06-09
- **Builds on:** RFC-0006 (self interface call `@@:self.method()`), RFC-0013 (`@@`/`@@:` syntax), RFC-0045 (`@@:system` reservation)

The key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are
to be interpreted as described in RFC 2119.

## Summary

`@@:self` becomes the **single, portable, framec-lowered** way to reference a
system from inside its own handlers — for **both** interface calls **and** domain
field access:

- `@@:self.method(args)` — call own interface method (RFC-0006, unchanged).
- `@@:self.field` — **new:** read/write a domain field, lowered to the target's
  native receiver (`self.`, `this.`, `this->`, `$this->`, `@`, record update…).

Correspondingly, a **bare native `self.` / `this.` self-reference is no longer a
blessed Frame construct.** Inside `@@system` handler bodies framec stops doing
*any* transform on bare `self.` — it is, again, ordinary native code that passes
through verbatim and is valid only on targets where the host language actually
defines `self` (Python, Rust, Swift, Lua, GDScript). The three bolted-on
`self.`→native **field** rewrites that currently contradict the verbatim
passthrough contract (C++ `this->`, Java `this.`, Erlang record update) are
**removed**; their job moves to the `@@:self.field` lowering, applied uniformly
to all 17 targets in one place.

This closes a real expressiveness hole (there was **no** portable way to touch a
field across targets), removes a class of silent miscompiles, and — most
importantly — makes `@@:self` the **only correct** way to self-call the
interface, because the deferred-transition guard that keeps a self-call safe is
emitted at the `@@:self` call site and is absent from a native self-call.

This is a **breaking change**, made deliberately before Frame has public users.

## Motivation

### 1. There is no portable way to reference a field

Frame's contract is verbatim passthrough of native code, with a small `@@:`
namespace of portable constructs that framec lowers per target. Field access fell
through the crack: the docs told authors to "access domain variables via
`self.field` / `this.field` / `this->field` (per target language)"
(`frame_language.md:517`). That is *per-target source* — a system that touches a
domain field cannot be written once and compiled to all 17 backends. Today:

```
machine:
    $Playing { tick() { self.score = self.score + 1; return; } }
```

compiles only on the five targets whose host language has a `self`
(Python, Rust, Swift, Lua, GDScript). On C++, C#, TypeScript, JavaScript, Kotlin,
Dart, PHP it emits a literal `self.` into a language with no `self` — a hard
compile error (issue **#69** is one instance of this class).

### 2. The "fix" so far has been to bolt transforms onto native code

Three backends grew ad-hoc rewrites of bare `self.field` into the native receiver
— C++ (`self.`→`this->`), Java (`self.`→`this.`, `java_native_rewrite.rs`), and
Erlang (record update, `erlang_system.rs`). These directly contradict the
verbatim passthrough contract ("framec transforms nothing in user source"): they
reach into native code and rewrite it. Worse, they are **inconsistent** — the
*same* `self.field` is silently rewritten on 3 targets and silently miscompiled
on 6 others, with the matrix green throughout because every fixture sidesteps the
issue by writing the native receiver directly. There is no portable construct, so
there is nothing portable to test, so the gap is invisible.

### 3. `@@:self` is the only *correct* self-call, not merely the portable one

This is the decisive reason, and it is about **correctness**, not style.

Per RFC-0006, `@@:self.method(args)` emits a **caller-side transition guard** at
the call site: after the self-call returns, if the callee transitioned, the
caller's remaining handler body is short-circuited
(`if ctx._transitioned: return;` on Python/TS; the
`case Data#data.frame_current_state of …` wrapper on Erlang). A **native**
`self.method()` / `this.method()` reaches the same generated interface wrapper
(so the transition *executes*), but it gets **no caller-side guard** — so the
caller's statements after the call keep running against a system that has already
left the state. That is a silent semantic bug.

`frame_language.md:790` currently claims native self-calls "produce the same
runtime behavior" because "the deferred-transition semantics live in the
generated interface wrapper, not in the `@@:self.` syntax." That is **wrong**: the
wrapper executes the deferred transition, but the *caller-side short-circuit* is
emitted by the `@@:self` syntax and only by it. This RFC corrects that text.

Therefore `@@:self.method()` MUST be the one blessed way to self-call the
interface, and native self-calls become unsupported (not merely non-portable).

## Design

### The rule, in one line

> Inside an `@@system`, `@@:self` is the only Frame self-reference. Everything not
> under `@@:` is verbatim native code. framec transforms `@@:self.…` and **nothing
> else**.

### Grammar

`@@:self` remains a syntactic prefix, never a bare value (RFC-0006: bare `@@:self`
is **E603**). It is always chained with a member:

```
@@:self.<member>            // member is resolved against the system's symbols
@@:self.<member>(args)      // call form
```

`<member>` resolution (the symbol table already distinguishes these):

| `<member>` is… | Meaning | Lowering |
|---|---|---|
| an **interface method** | reentrant kernel dispatch + caller-side transition guard | RFC-0006 (unchanged) |
| a **domain field** | direct field access | native receiver prefix (this RFC) |
| an **embedded sub-system field** | field access; the trailing `.method()` is a native call on the sub-system | receiver prefix + native deref (this RFC) |
| neither | **error** (see Validation) | — |

### Field lowering table

`@@:self.<field>` (read or assignment LHS) lowers to the target's native
receiver-prefixed field. framec already knows each target's receiver — this is the
same mapping the three bolted-on rewrites encoded, now unified:

| Target | `@@:self.score` | `@@:self.score = x` |
|---|---|---|
| Python, Rust, Swift, Lua, GDScript | `self.score` | `self.score = x` |
| TypeScript, JavaScript, Java, Kotlin, C#, Dart | `this.score` | `this.score = x` |
| C++ | `this->score` | `this->score = x` |
| PHP | `$this->score` | `$this->score = x` |
| C | `self->score` | `self->score = x` |
| Go | `<recv>.score` | `<recv>.score = x` |
| Ruby | `@score` (read) / `self.score = x` or `@score = x` (write) | per accessor convention |
| Erlang | `Data#data.score` (read) / record update (write) | record-update threading |

The lowering happens at the **`@@:self` expansion site**, the same place
`@@:self.method()` is already lowered — not inside the native-code stream. The
verbatim passthrough scanner is untouched: it still recognizes `@@:` as a Frame
token and leaves every other byte alone.

### Embedded sub-systems (the #69 case, generalized)

```
domain:  ship: Ship = @@Ship()
machine: $Playing { tick() { @@:self.ship.respawn(); return; } }
```

`@@:self.ship` lowers to the native receiver for the `ship` field. On targets
where an embedded system is held by pointer/handle the field lowering carries the
deref:

- C++ (`std::shared_ptr<Ship>`): `@@:self.ship` → `this->ship->`, so
  `@@:self.ship.respawn()` → `this->ship->respawn()`.
- PHP: `$this->ship->respawn()`. Others: `this.ship.respawn()` /
  `self.ship.respawn()` per receiver.

The `.respawn()` itself is a native call on the sub-system's generated public
method. The deref that PR #70 special-cased in the C++ handler emitter becomes a
natural consequence of the single field-lowering rule.

### Validation — strict in v1 (E609)

`@@:self.<member>` is **already parsed into structured AST**: the context-parser
FSM (`native_region_scanner/context_parser.frs`, state `$ParseSelf`) recognizes
`@@:self.<name>` and scans the member identifier — the call form
`@@:self.method()` captures the method name in `ContextSelfCall { method, … }`,
and the accessor form `@@:self.<name>` is already segmented as `ContextSelf`. The
member name is therefore in framec's hands, not in the opaque native stream. And
arcanum carries both `interface_methods` and `domain_symbols` for every system.

Because resolution is fully available at compile time, validation ships **strict
in v1**:

- **E609 — `@@:self.<name>` references no known interface method or domain
  field.** (Number tentative; next free after RFC-0045's E608.)

The only parser change is to promote the already-scanned member identifier from
"inside the `ContextSelf` span" to a named field on the segment — exactly
mirroring how `ContextSelfCall` already records `method`. This is a strict
improvement over native passthrough, which silently emits `this->typo` and defers
the error to the host compiler (or, on dynamic targets, to runtime).

### Removal of native `self.` as a blessed construct

- framec **MUST NOT** transform bare `self.` / `this.` in handler bodies. The
  C++/Java/Erlang field rewrites are deleted; the C++ work from PR #70 (and its
  part-1 predecessor) is reverted.
- Bare `self.field` remains *legal native code* — it simply is not portable and
  is valid only where the host language defines `self`. framec neither blesses nor
  rewrites it.
- Native `self.method()` self-**calls** are **unsupported**: they miss the
  caller-side transition guard (Motivation §3). framec does **not** police this —
  it does not inspect native code, so it neither warns nor errors on a native call
  to one of the system's own methods. A native self-call is the author's native
  code, and its consequences (no transition guard) are theirs. `@@:self.method()`
  is documented as the blessed, correct form; choosing native instead is choosing
  to forgo the guard. (framec *cannot* reliably detect a self-call in native code
  anyway — `x.method()` is undecidable in general — so a detector would be both a
  passthrough violation and unsound.)

## Migration

This is a pre-public breaking change; no published Frame program is affected.
framec's own demos, fixtures, and docs migrate mechanically:

1. **Field access → portable:** `self.field` / `this.field` / `this->field` /
   `$this->field` in handler bodies → `@@:self.field`. (A one-shot codemod can do
   this; the native receiver is recoverable from the target.)
2. **Self-calls → blessed:** any native `self.method()` / `this.method()` that
   targets the system's own interface → `@@:self.method()`.
3. **Targets that keep `self`** (Python/Rust/Swift/Lua/GDScript): existing
   `self.field` still compiles, but is migrated to `@@:self.field` for
   portability and to silence the new self-call warning where applicable.

Per-language guides drop every "Frame's `self.field` lowers to X" claim (they
currently teach the now-removed rewrite — `php.md:80`, `csharp.md:50`,
`cpp.md`, etc.) and instead teach: *write `@@:self.field` for portable field
access; bare `self.` is native and non-portable.* `frame_language.md:517` and
`:790` are rewritten per Motivation §1 and §3.

## Drawbacks

- **Verbosity.** `@@:self.score = @@:self.score + 1` is heavier than
  `self.score = self.score + 1`. The cost lands only on authors writing
  cross-target systems, who currently cannot express field access portably at all.
- **Churn.** Deleting three established rewrites and migrating fixtures/docs is
  non-trivial, and the matrix must be re-greened with the *portable* construct
  actually exercised on all 17 targets (which is the point — the gap that hid #69
  closes structurally).

## Alternatives considered

1. **Keep bolting on per-target `self.field` rewrites** (the #69 trajectory).
   Rejected: it is the verbatim-passthrough violation, it is inconsistent across
   targets, and it never produces a portable, testable construct — so it cannot
   fix the self-**call** correctness bug at all.
2. **Auto-prefix bare field names** (extend `frame_language.md:292`'s
   `value = value` → `self.value = value` behavior to all field references).
   Rejected: it requires framec to parse and rewrite native code to find bare
   identifiers that happen to be fields — the opposite of passthrough — and it
   still gives the self-**call** no guard.
3. **Make native self-calls emit the guard** (teach the scanner to find
   `self.method()` and inject the short-circuit). Rejected: same passthrough
   violation, and undecidable in general (is `x.method()` a self-call?).

## Decisions (resolved)

- **D1 — Staged rollout (was O1).** Land in stages, keeping the matrix green at
  each step: **(a)** add the `@@:self.field` lowering (+ E609) on all 17 targets;
  **(b)** migrate framec's own fixtures, demos, and docs from native `self.field`
  to `@@:self.field`; **(c)** delete the three bolted-on native-`self.field`
  rewrites (C++/Java/Erlang) and revert PR #70. Each stage is independently
  validated against the full matrix.

- **D2 — No policing of native self-calls (was O2).** framec does not inspect
  native code, so it neither warns nor errors on a native `self.method()`. See
  *Removal of native `self.`* above. We don't police authors' calls to their own
  objects; `@@:self.method()` is documented as the blessed form and that is the
  extent of framec's involvement.

- **D3 — E609 strict in v1 (was O3).** `@@:self.<member>` is already parsed into
  structured AST and arcanum carries the symbols to resolve it, so unknown-member
  rejection (E609) ships with the initial lowering. See *Validation* above.

### Remaining work item to confirm during implementation (O4)

**Field-*write* lowering on Ruby and Erlang is not a simple receiver prefix.** The
*read* side of `@@:self.field` is a uniform "prefix the native receiver." The
*write* side (`@@:self.field = expr`) diverges on two backends and **MUST** reuse
each backend's existing domain-field assignment codegen rather than a textual
prefix:

- **Ruby.** Reading is `@field` (instance variable). Writing `@@:self.field = x`
  must lower to `@field = x` (direct ivar write), **not** `self.field = x` — the
  latter calls a `field=` setter method that exists only if the backend declared
  an `attr_writer`/`attr_accessor`. The lowering must match how framec's Ruby
  backend actually declares domain fields (plain `@ivars` vs accessors) so reads
  and writes agree.
- **Erlang.** There are no mutable fields. A domain field lives in an immutable
  `#data{}` record threaded through the handler. Reading is `Data#data.field`;
  "writing" `@@:self.field = x` is **not** an assignment — it must produce a new
  binding `DataN = Data#data{field = x}` and thread `DataN` forward to every
  later reference (the existing `data_gen` machinery, e.g.
  `Data1 = Data#data{score = Data#data.score + 1}`). So the write lowering hooks
  into data threading, not a prefix.

Confirm during implementation that the `@@:self.field` write path delegates to the
same domain-field assignment codegen these backends already use for initializers
and native domain writes, so there is no second, divergent code path.

## Acceptance

- `@@:self.field` lowers correctly on all 17 backends (read + assignment LHS +
  embedded-system deref), proven by a single portable fixture compiled and run on
  every target in the matrix — the construct that was missing.
- The three native-`self.field` rewrites are gone; `grep` finds no
  `self.`→receiver rewrite in codegen.
- `@@:self.method()` remains correct (RFC-0006 guard intact); native self-calls
  produce the new advisory (O2).
- Docs carry no "`self.field` lowers to X" claim; `frame_language.md:517/:790`
  corrected.
