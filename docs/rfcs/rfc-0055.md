# RFC-0055: Persistence architecture — faithful save/restore and per-language type identity

> **⚠ DEPRECATED — superseded by [RFC-0056](rfc-0056.md). Do not use this document as the basis
> for new work.** Its per-language regime analysis (static vs. reflective vs. non-reflective) is
> sound and is **carried forward** into RFC-0056; but its "persist-anything" framing and
> two-tier ambition overreached the current goal. RFC-0056 scopes persistence to single-language
> round-trip, makes delegation to the host serializer the explicit rule, and defers graphs /
> cycles / a portable owned format as separate future work rather than part of the contract.

- **Status:** Superseded by [RFC-0056](rfc-0056.md)
- **Author:** Mark Truluck <mark.truluck@cogiton.com>
- **Created:** 2026-07-10
- **Builds on:** RFC-0012 (the persist contract), RFC-0053 (faithful persistence), RFC-0054 (persistence type manifest), RFC-0016.1 (`@@[no_persist]`), RFC-0015 (factory-only construction)

The key words **MUST**, **MUST NOT**, **SHOULD**, **RECOMMENDED**, and **MAY** are
to be interpreted as in RFC 2119.

## Summary

Frame persists a [system](../glossary.md#system) and the objects it holds, and
restores them into an environment running the same schema and types. The goal is
**best-fidelity, persist-anything** save/restore built from two tiers:

- an **automated tier** that round-trips everything tree-shaped — primitives,
  user-defined types, nesting, and collections — with no user code where the
  target permits; and
- a **manual tier** — a user-authored operation — for what no automated scheme can
  serialise: cross-object relationships (graphs) and live resources (sockets, file
  handles).

The automated tier turns entirely on one question — **where does the type identity
of a persisted value come from?** — and the answer is **not the same in every
language**. Restoring a value to its correct type requires knowing *which* type to
reconstruct; each target supplies that knowledge from a different place, and some
cannot supply it at all without help. This RFC lays out that problem space in
detail (§Motivation), then defines the contract that draws from the
**highest-fidelity source each language offers** (§The contract): a runtime type
tag where the language can reflect it, a declared type plus a self-marshalling
requirement where it cannot.

## Motivation

### The core problem: identity must survive the round-trip

A [snapshot](../glossary.md#snapshot) is a flat byte stream. On **save** you hold a live object and can read
whatever the language exposes about it; on **restore** you hold only bytes and must
decide *which type* to reconstruct **before** you can rebuild it. So the type
identity of every persisted value must reach the restore site somehow. There are
exactly two channels:

1. **In the code** — framec knows the value's type at generation time and bakes the
   reconstruction (`restore as Vec2`) into the emitted program. The byte stream
   carries pure data.
2. **In the bytes** — the value's type name travels *in* the snapshot (a tag), and
   restore reads it to route reconstruction.

Which channel is available is a property of the *language*, and it decomposes into
four runtime capabilities:

- **C1 — compile-time type:** does framec know the field's type when it generates
  the code? (True where the target is statically typed and the field is declared.)
- **C2 — runtime type naming:** can the running program name a value's own type on
  save? (Needed to write a tag.)
- **C3 — name resolution:** can the program turn a type-name string back into that
  type on restore? (Needed to read a tag.)
- **C4 — reconstruction:** can the program build an instance without running its
  constructor and populate its fields? (Needed either way.)

C4 holds nearly everywhere. C1 splits static from dynamic targets. The decisive,
and frequently overlooked, split is **C2/C3 among the dynamic targets** — because a
dynamically-typed language, where framec has no compile-time type (¬C1), can only
use the in-bytes channel, and the in-bytes channel *requires C2 and C3*. Not every
dynamic language has them.

### The three regimes

Combining the capabilities yields three [regimes](../glossary.md#regime), and every
supported target falls into one:

- **Regime A — Static (C1).** framec has the field's type at generation and bakes
  it; the bytes are pure data, no tag. Fidelity is the *declared* type.
- **Regime B — Dynamic + reflective (¬C1, C2, C3).** framec has no compile-time
  type, but the runtime can name a value's type on save and resolve it on restore.
  The type travels as an in-bytes tag capturing the value's **runtime** type — the
  *highest* fidelity available, because it preserves the actual concrete type
  (including a subtype stored in a base-typed field), reconstructs nesting and
  collections automatically, and asks nothing of the user.
- **Regime C — Dynamic + non-reflective (¬C1, ¬C2 / ¬C3).** framec has no
  compile-time type *and* the runtime cannot name or resolve a value's type. Neither
  channel works on its own. The type identity must be supplied **by declaration**
  (framec bakes the declared field type, as in Regime A) and, for anything nested,
  **by the type marshalling itself** (or by explicit registration). This is the
  regime that is easy to miss and the reason a blanket "the tag comes from
  reflection" is false.

### The problem space, per target

The 16 supported targets (Erlang is deprecated and excluded — it persists natively
via `gen_statem` and is out of scope):

| Target | Typing | C1 compile-time type | C2 name a value's type (save) | C3 resolve name→type (restore) | Type-identity source | Fidelity | Marshalling route |
|---|---|---|---|---|---|---|---|
| Rust | static | ✅ | — | — | declared type, baked | declared | serde derive/impl |
| Swift | static | ✅ | — | — | declared type, baked | declared | `Codable` |
| C++ | static | ✅ | — | — | declared type, baked | declared | ADL `to_json`/`from_json` |
| C | static | ✅ | — | — | declared type, baked | declared | `pack`/`unpack` hooks |
| Dart | static | ✅ | — | — | declared type, baked | declared | `toJson`/`fromJson` |
| Go | static | ✅ | — | — | declared type, baked | declared | struct tags / `Marshaler` |
| Java | static | ✅ | — | — | declared type, baked | declared | bean / registered codec |
| Kotlin | static | ✅ | — | — | declared type, baked | declared | bean / registered codec |
| C# | static | ✅ | — | — | declared type, baked | declared | attributes / converter |
| Python | dynamic | ❌ | ✅ `type(o).__qualname__` | ✅ module scan | **runtime tag** | **runtime** | reflection (automatic) |
| Ruby | dynamic | ❌ | ✅ `o.class.name` | ✅ `ObjectSpace` | **runtime tag** | **runtime** | reflection (automatic) |
| PHP | dynamic | ❌ | ✅ `get_class($o)` | ✅ declared-classes | **runtime tag** | **runtime** | reflection (automatic) |
| JavaScript | dynamic | ❌ | ✅ `o.constructor.name` | ⚠️ live-graph seed + hook | **runtime tag** | **runtime** | reflection (automatic) |
| TypeScript | dynamic | ❌ | ✅ `o.constructor.name` | ⚠️ live-graph seed + hook | **runtime tag** | **runtime** | reflection (automatic) |
| Lua | dynamic | ❌ | ⚠️ metatable `__name` **by convention** | ⚠️ seed + registration | tag-by-convention / registration | declared | registered codec |
| GDScript | dynamic | ❌ | ❌ `get_class()` = engine base, not the user type | ❌ **explicit registration only** | **declaration / registration** | declared | registered codec |

Reading the table:

- **Nine static targets (Regime A):** the declared type is the source. This is not a
  new requirement — the native code cannot compile without the type — so these
  targets already carry it. Two sub-behaviours worth noting: some enforce a
  serialisable type at build time (Rust/Swift/C++/C/Dart), while others reflect at
  run time (Go/Java/Kotlin/C#) — and **Go in particular fails *silently***: a type
  whose fields are not visible to its JSON encoder marshals to `{}` and restores to
  zero values with no error. That silent data loss is a fidelity defect to fix
  (§Migration), independent of anything proposed here.
- **Five dynamic reflective targets (Regime B):** Python, Ruby, PHP, JavaScript,
  TypeScript. The runtime tag is the source, and it is the **best** available — it
  captures the concrete runtime type and rebuilds nested user types and collections
  of user types automatically, with no annotations and no marshal code. JavaScript
  and TypeScript are the weak case of C3: their module system cannot enumerate
  types, so they seed the registry from the *live object being restored into* plus an
  optional registration hook. This is **incomplete** — a persisted type not reachable
  from the fresh restore target's initial graph (e.g. a field that defaults to `null`
  but held a user object at save time) is not seeded and is falsely refused (E750),
  even though it is module-defined. The registration hook is a manual workaround; the
  declared field type (R1) is the reflection-free fix, letting framec seed the
  registry from the declaration rather than the live graph. Because JS/TS cannot
  enumerate their own module types, R1 is therefore **MUST** on them (not merely
  RECOMMENDED as on the enumerating Regime B targets) — they sit with Regime A/C on
  the requirement axis even though they carry a runtime tag like the rest of Regime B.
- **Two dynamic non-reflective targets (Regime C):** Lua and GDScript. **GDScript
  cannot name a user type at all** — `get_class()` returns the engine base class —
  which is why it already **requires the user to register** each persistable type
  and refuses an unregistered one on save. **Lua** has no class system; a value's
  type name exists only if the user's metatable sets `__name`. In this regime the
  automated tier cannot function on reflection; it needs the type identity supplied
  by **declaration** and nested reconstruction supplied by **the type itself**.

The lesson the table makes explicit: **the type-identity source is a per-language
fact, and there is no single mechanism.** A contract that assumes reflection is
universal is wrong for GDScript and fragile for Lua; a contract that mandates
declared-type baking everywhere throws away the runtime tag's superior fidelity in
Regime B. The correct contract draws from the best source **each regime** offers.

## The contract

### The automated tier — draw from the best available source

For every persisted field, framec obtains the type identity from the highest-fidelity
source the target supports:

- **Regime A (static):** framec bakes the field's declared type into restore. No tag.
- **Regime B (dynamic reflective):** framec's generated save writes an in-bytes tag
  from the value's runtime type; restore resolves it against the program's own types
  (closed-world; see Security) and rebuilds. No annotations, no marshal code; nested
  user types and collections carry their own tags and reconstruct recursively.
- **Regime C (dynamic non-reflective):** framec bakes the field's *declared* type
  (as in Regime A), and each nested user type reconstructs itself through its
  declared marshalling route. This is the reflection-free path.

This yields two requirements, and — the point of this RFC — they are **conditional
on regime**, not universal mandates:

> **R1 — Declared field type.** A persisted field **MUST** carry a declared type
> (`name: Type`) on any target that **cannot enumerate its own module's types at
> restore** — because there the declaration is the field's only identity source
> (Regime A / Regime C) or the only reflection-free way to seed the closed-world
> registry (the JavaScript/TypeScript subset of Regime B). Concretely R1 is MUST on:
> every Regime A (static) target; both Regime C targets (Lua/GDScript); **and
> JavaScript/TypeScript**, whose ES module system cannot enumerate its class
> declarations, so the registry would otherwise be seeded only from the live object
> being restored into — the incomplete walk that falsely refuses a module-defined
> type held in a `null`-defaulting field (E750, #182). On the **enumerating** Regime
> B targets — **Python, Ruby, PHP** — a declared type is **not required** for
> reconstruction (the runtime tag supplies the identity and a module-class scan —
> Python `vars(module)`, Ruby `ObjectSpace`, PHP `get_declared_classes()` — resolves
> it) but remains **RECOMMENDED** for cross-target portability and schema-drift
> completeness (an untyped field is invisible to the drift fingerprint). The
> exemption is `@@[no_persist]` (below): a field opts out of R1 by opting out of
> persistence. framec enforces R1 as **E752**.

> **R2 — Self-marshalling types.** A persisted user-defined type **MUST** be
> serialisable through its host language's standard route on any Regime A or Regime C
> target — declared, derived, or hand-written (serde derive, Swift `Codable`, Go
> tags, C/C++ hooks, a GDScript/Lua registration). Auto-derivation satisfies R2, and
> — on Regime A — it **composes recursively**: a derived/annotated serialiser
> reconstructs nested *concrete* user types automatically (serde, `Codable`, Jackson,
> `encoding/json` all do this), so plain nesting needs no hand-written marshal there.
> A hand-written marshal on a Regime A target is needed only for a **polymorphic /
> interface-typed field** (to recover the concrete subtype — a tagged enum,
> `@JsonTypeInfo`) or for **internal sharing / cycles**. On **Regime C** even plain
> nesting needs work, because its registration route is *non-compositional* — each
> nested user type must be separately registered. On Regime B targets R2 is **not
> required** — reflection marshals the type automatically — though a type **MAY**
> provide a marshal to override the default encoding.

The design intent: **the enumerating Regime B targets (Python/Ruby/PHP) pay nothing**
(the tag and a module scan do everything, at best fidelity); **JavaScript/TypeScript
pay only R1** (the declared type — their non-enumerable modules need it as the
reflection-free registry seed; R2 they still get for free from reflection); **Regime A
already complies** (the native code demands the type and a serialisable shape);
**Regime C** is where R1+R2 do real work — they are the
reflection-free substitute for the tag, and they **subsume and improve on** the
registration those targets require today (framec derives what to reconstruct from
the declaration instead of asking the user to register it).

### The manual tier — for what cannot be serialised

Two categories are, by design, the system's own responsibility, because no automated
scheme can reach them:

- **External resources.** A live socket, file handle, or connection has no
  serialisable state; it is *re-acquired*, not restored. Tag the field
  [`@@[no_persist]`](../glossary.md#no_persist): it is excluded from the byte stream
  and restored to its [domain](../glossary.md#domain) default (typically null). A
  regular operation the system declares (e.g. `reattach()`) re-acquires it after
  [load](../glossary.md#load). Frame provides no implicit hook by decision (RFC-0012);
  reattachment may equally be modelled as an event driving a "reconnecting"
  [state](../glossary.md#state).
- **Cross-object graphs and relationships.** framec serialises each field
  independently, so two *different* fields aliasing one object cannot be reconciled
  automatically: a shared reference **duplicates** into two independent objects
  (identity lost), and a true cycle **fails** — the encoder refuses (Python `json`
  raises "Circular reference detected") or aborts (some encoders stack-overflow), but
  it never silently succeeds. A type's
  own marshal can encode a reference table for its *internal* sharing, but
  cross-field identity is not an automated guarantee. A system that must restore a
  graph rebuilds it in the same kind of user operation used for resources.

These are one category — "structure and effects framec cannot see" — with one tool:
a user-authored operation framec knows nothing about. This is what makes the
paradigm **persist-anything**: automated where the language permits, manual where it
does not, with a clean boundary between them.

### The snapshot — the persisted data structure

Two terms, distinct:

- The **snapshot** is the whole persisted structure — the value `save` returns and
  `load` consumes (its host type is set by `@@[persist(<type>)]` — a string, a byte
  buffer, etc.). It carries the complete recoverable runtime state.
- The [**manifest**](../glossary.md#manifest) is *one field inside the snapshot* (`_manifest`). It carries **no
  state data** — it is a fingerprint of the type *shape* used only for drift
  detection (below). "Snapshot" is the data; "manifest" is the schema token within
  it.

#### Envelope

The snapshot's top level holds four kinds of member:

- `_compartment` — the **active** [compartment](../glossary.md#compartment): the
  live per-state data record, which recursively contains its hierarchical parent
  via `parent_compartment` (the HSM chain).
- `_state_stack` — an ordered list of compartments pushed onto the modal stack
  (`push$`/`pop$`), each a full compartment.
- `_manifest` — the type-shape fingerprint (see below).
- one member **per persisted domain field**, keyed by field name. A domain field
  that is itself a nested `@@system` is inlined as that child's own snapshot.

#### Compartment (recursive)

Each compartment records the runtime data of one active state:

- `state` — the state name; the **routing key** for type-directed reconstruction.
- `state_vars` — the `$.` variables, keyed by name.
- `state_args` — the state's parameters, positional (by index).
- `enter_args` — the `$>` enter-handler arguments, positional.
- `exit_args` — the `$<` exit-handler arguments, positional.
- `parent_compartment` — the enclosing HSM compartment, or null at the root.

Backends vary slightly in one member: the compiled Go and JavaScript backends also
serialise a `forward_event` member into every compartment (null in a persisted,
quiescent system), which the reflective backends (e.g. Python) elide. The worked
example below is a Python snapshot and so omits it.

Compartment data — including a user-typed state variable on a *pushed-and-persisted*
compartment — round-trips at the same fidelity as domain fields.

#### Value encoding (by regime, per §Motivation)

- Primitives and native collections serialise directly.
- A user-typed value on a **Regime B** target carries an in-bytes type tag
  (`__frame_type__`) beside its fields; nested user types and collection elements
  each carry their own tag and reconstruct recursively.
- A user-typed value on a **Regime A** target is pure data (no tag); its declared
  type drives reconstruction.
- A user-typed value on a **Regime C** target *currently* also carries an in-bytes
  tag — sourced from a metatable-`__name` convention (Lua) or an explicit
  registration (GDScript), not from reflection — because that is the only type
  identity available today. Under the R1/R2 migration below, framec reconstructs
  such values from the declared type instead, and the Regime C tag falls away.

#### Worked snapshot

A real snapshot (Python, a Regime B target) from a system whose `$Idle` state holds a
user-typed state variable `$.sv: Vec2`, pushes onto the stack, and transitions into
`$Active` over an HSM parent `$Base`:

```json
{
  "_compartment": {
    "state": "Active",
    "state_args": [],
    "state_vars": {},
    "enter_args": [],
    "exit_args": [],
    "parent_compartment": {
      "state": "Base",
      "state_args": [],
      "state_vars": {},
      "enter_args": [],
      "exit_args": [],
      "parent_compartment": null
    }
  },
  "_state_stack": [
    {
      "state": "Idle",
      "state_args": [],
      "state_vars": { "sv": { "__frame_type__": "Vec2", "x": 3.0, "y": 4.0 } },
      "enter_args": [],
      "exit_args": [],
      "parent_compartment": null
    }
  ],
  "_manifest": "frame-persist-manifest:1|S6:Active|V|A|E|X|S4:Base|V|A|E|X|S4:Idle|V2:sv4:Vec2|A|E|X|D6:marker3:int",
  "marker": 1
}
```

`_compartment` is the active `Active` over its parent `Base`; `_state_stack` holds the
pushed `Idle` with its live `Vec2` state variable; `marker` is a persisted domain
field; `_manifest` is the fingerprint, carrying no data.

#### The manifest field and drift protection

Every persisted field's declared type is recorded once in the **type manifest**
(RFC-0054) and serialised into `_manifest` as an order-insensitive, length-prefixed
fingerprint: a format version, then per state (sorted by name) its typed state
variables, state / enter / exit arg types, and finally the domain field types —
each entry length-prefixed so no delimiter can be confused with a type name. It
holds type *identity*, never values. Sorting-then-fingerprinting is the standard
*canonical-form-before-hash* discipline (cf. Avro's Parsing Canonical Form and its
CRC-64 fingerprint, Confluent Schema Registry ids). On restore, a mismatch between
the snapshot's fingerprint and the program's own is refused as schema drift — so
"same schema" is verified, not assumed. This is deliberately **stricter** than Avro
reader/writer resolution or Protobuf compatibility, which *tolerate* a compatibly
evolved schema: an equality-refuse fingerprint gives **detection**, not
**resolution** — resolving drift (migration) is a separate, deferred effort. R1
strengthens this from "records the type where declared" to
"records every field's type," making the fingerprint a complete schema description
on every target where R1 is MUST (Regime A/C and JavaScript/TypeScript).

### Security is a property, not a driver

Persistence is not a security feature, and security is not a design goal of this RFC;
it is a property the automated tier must preserve. Wherever a type name travels in
the bytes, it is attacker-controllable, so restore resolves it **only** against the
program's own types (a closed world), refuses a foreign name, and reconstructs
without running the type's constructor — so a hostile snapshot cannot instantiate
arbitrary types or run initialisation code. This is the accepted mitigation for the
deserialisation attack class (the reason `BinaryFormatter` was withdrawn and
polymorphic `TypeNameHandling`/gadget chains are CVEs); framec's allow-set is
*tighter* — the program's own module, not a user-configured list. It applies in
**Regime B** and **also in Regime C today**, whose tag (Lua metatable-`__name`,
GDScript registration) is likewise resolved closed-world against the registration
table; **Regime A** carries no tag at all. The residual, bounded blast radius is the
one the field expects and no more: attacker-controlled *field values* written into a
legitimate own-type object — never a foreign type, never code execution. A snapshot
is untrusted input, not to be trusted. framec never inspects a user type's fields in
any regime; the [Oceans model](../glossary.md#oceans-model) (RFC-0026) holds — a type
name is an opaque, verbatim string throughout, and R1/R2 add nothing to what framec
knows about a type, only to what the *user* declares.

## Examples

A system with a user-typed [domain](../glossary.md#domain) field and a resource:

```
@@[persist(str)]
@@[save(save_state)]
@@[load(restore_state)]
@@system Session {
    operations:
        reattach()          // manual tier: re-acquire the resource after load
    interface:
        record(v: Sample)
    machine:
        $Active {
            record(v: Sample) { ... }
        }
    domain:
        history: Log = Log()      // user type; automated tier
        @@[no_persist]
        socket: Conn = null       // resource; excluded, reattached manually
}
```

- On **Python** (Regime B): `history` round-trips automatically — its runtime type
  and its nested contents are tagged and rebuilt with no marshal code. `socket` is
  excluded; the program calls `reattach()` after restore.
- On **Go** (Regime A): `Log` must be a serialisable struct — exported fields are
  enough (R2); `encoding/json` composes over any concrete nested types, and a custom
  `Marshaler` is needed only for a polymorphic field or internal sharing. framec
  bakes `Log` reconstruction from the declared type.
- On **GDScript** (Regime C): `history: Log` must be typed (R1) and `Log` must have a
  registered marshalling route (R2); framec reconstructs from the declaration rather
  than requiring a hand-registered tag.

## Alternatives

- **"Reflective backends are the anomaly; require a universal marshalling
  interface."** An earlier draft of this RFC claimed the reflective targets were the
  exception and that eleven of thirteen host languages already required a
  serialisation interface. Measurement refuted it: the true split is three regimes,
  reflection-based automation is the *majority* behaviour, and only a minority of
  targets require a declared interface. Rejected — the premise was false.
- **Mandate declared-type baking on every target (drop the runtime tag
  everywhere).** This would unify the mechanism, but it *lowers* fidelity in Regime B
  — the declared type loses the concrete runtime type (a subtype in a base-typed
  field) — and forces hand-written marshals for nesting that reflection handles for
  free. Rejected — it trades away the best available fidelity for uniformity.
- **Drive the design from shrinking the in-bytes attack surface.** Eliminating the
  Regime B tag would remove the closed-world surface, but that surface is already
  guarded (closed-world resolution + constructor bypass), and security is not the
  goal. Rejected — it optimises a non-objective at fidelity's expense.
- **Automated reference-preservation for graphs (a memo / `$id`-`$ref` / two-pass
  restore).** The established fix for shared references and cycles — pickle's memo,
  .NET `ReferenceHandler.Preserve`, Jackson `@JsonIdentityInfo`, JSON-LD `@id` — is a
  snapshot-wide object-identity map plus an allocate-then-link second pass. Rejected
  *for the automated tier*: framec serialises each field independently, so a global
  identity map spanning independently-marshalled fields would break per-field
  independence, and no uniform such map exists across the Regime A/C declared-marshal
  targets — framec would have to own graph traversal over the user's opaque types,
  crossing the Oceans boundary. A type that needs it implements the reference table
  in its *own* marshal (its internal identity is knowable to it), and cross-object
  graphs are handled in the manual tier — the delegation this RFC adopts instead.

## Migration

R1 and R2 are already satisfied on the nine static targets and cost nothing on the
five reflective targets. They bind only where the language cannot reflect — Lua and
GDScript — and there they **replace** the registration burden those targets already
carry, so for a correctly-written Regime C program they are a net simplification. A
program that omits a field type today is, in effect, locked to Regime B targets;
making R1 explicit surfaces that as a diagnostic rather than a silent portability
cliff.

Suggested staging: **warn** (diagnose an untyped persisted field or a
non-serialisable user type on a target that needs it) → **opt-in strict** → **default
strict**. Independently and immediately: fix the **Go silent-drop** defect so a
non-serialisable persisted type fails loudly rather than losing data.

## Non-goals

- Restoring a snapshot whose schema differs from the running program (cross-version
  migration).
- Reviving a snapshot saved by a different target language.
- Modelling a user type's fields, cross-object identity, or a language-neutral type
  identity — the Oceans model holds; the type is an opaque string.
- Removing `@@[no_persist]` or the manual operation — that is the answer for values
  with no serialisable form.
