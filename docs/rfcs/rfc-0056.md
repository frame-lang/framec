# RFC-0056: Persistence — delegate to the host serializer; framec owns only the frame

- **Status:** Draft
- **Author:** Mark Truluck <mark.truluck@cogiton.com>
- **Created:** 2026-07-15
- **Supersedes:** [RFC-0053](rfc-0053.md), [RFC-0054](rfc-0054.md), [RFC-0055](rfc-0055.md)
- **Builds on:** [RFC-0015](rfc-0015.md), [RFC-0016.1](rfc-0016-1.md)

The key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** are to be
interpreted as in RFC 2119.

## Summary

Frame persistence saves a `@@[persist]` system and restores it into a **fresh instance of the
same program, in the same language**, indistinguishably. framec does **not** implement
serialization. It delegates the marshalling of every value to that language's **own best
serializer**, and confines its own generated code to the things a serializer cannot know: which
fields persist, the machine's live [**control state**](../glossary.md#control-state), restoring
**without running the constructor**, and — only in languages whose runtime cannot otherwise
recover a value's type —
supplying **type identity** safely. Cross-language portability and any framec-owned wire format
are **out of scope**.

This RFC is the **authoritative reference** for Frame persistence: it subsumes the faithful-restore
contract ([RFC-0053](rfc-0053.md)), the type manifest ([RFC-0054](rfc-0054.md)), and the
per-language regime architecture ([RFC-0055](rfc-0055.md)), which are deprecated. It covers the
contract, the three regimes, the full snapshot data structure (envelope, recursive compartment,
value encoding, manifest/drift), polymorphism, security, the diagnostics, and the deferred layers —
so the whole design lives in one place.

## Motivation

Persistence has been re-litigated repeatedly, and the cause is a single conflation. Earlier
designs aimed at a **uniform, framec-owned persistence format** spanning every target. That goal
silently demands three things that cannot all be true at once:

1. **type-ignorance** — framec writes no per-type serialization code;
2. **faithful user types** — a user-defined type, nesting, and collections all round-trip;
3. **no dependency** — framec borrows nothing from the target's ecosystem.

You can have any two. The attempt to have all three produced a hand-rolled "flat format" that
handled only scalars and, to do even that, branched on the field's type — violating (1) — while
a genuinely good, framec-owned envelope carried Python. The result was an **inconsistent hybrid
nobody could reason about**: one target served by a real mechanism, others by a scalar stopgap
wearing the same name.

The way out is to name the actual goal and drop the false one:

- The goal is **single-language round-trip**. That is achievable today.
- A **portable, cross-target, framec-owned format** is a different and far larger ambition. It
  is not required for single-language round-trip, and pursuing it is what kept resurrecting
  "should we build our own serializer?"

And the answer to that question is **no**. For a single language, the best serializer is that
language's own library — serde, `Codable`, `encoding/json`, `System.Text.Json`, Jackson. framec
will not equal or beat them and should not try. framec's value is not a serializer; it is
knowing the **Frame-specific** things a serializer does not.

## The contract

### Scope

- A snapshot produced by a program **MUST** restore into a **fresh instance of the same system,
  compiled from the same source, in the same language**, reproducing all observable state.
- Cross-language restore — a snapshot from target *X* revived in target *Y* — is **out of
  scope**. framec defines **no** portable wire format, and no target's snapshot bytes are a
  contract another target must read.

### The delegation principle

- framec **MUST NOT** implement value serialization. For every persisted value, the target
  language's **standard serializer** performs the marshalling of that value.
- framec's emitted persistence code **MUST** be **type-ignorant**: it emits the user's declared
  field types verbatim, plus whatever derive/attribute the serializer requires (e.g. Rust's
  `#[derive(Serialize, Deserialize)]`), and contains **no branch on a user type name**.
- **The rule:** *framec builds its own persistence mechanism only to supply a capability the
  host language lacks. It **MUST NOT** re-implement a serializer the host already provides.*

### What framec owns — on every target

A serializer knows how to turn a value into bytes. It does not know these, so framec **MUST**:

- **Field selection** — persist exactly the `domain:` fields that are not marked
  `@@[no_persist]`.
- **Control state** — the live machine position, in **full**. This is **not** merely the
  current state's name. It is the entire [compartment](../glossary.md#compartment) — the state
  identity, its [state variables](../glossary.md#state-variable), and its state-args / enter-args
  / exit-args, plus the parent-compartment link — **and**, for a state-stack machine, the whole
  **stack of compartments** beneath it. All of it **MUST** round-trip. (`@@[no_persist]` excludes
  a *domain* field; it never excludes compartment bookkeeping, which is always persisted.) No
  general-purpose serializer models any of this — it is framec's to serialize and rebuild.
- **Construction bypass** — restore **MUST** populate a fresh instance **without** running the
  user's `$>`/constructor (consistent with factory-only construction, [RFC-0015](rfc-0015.md)),
  so restoring cannot re-fire lifecycle side effects. Concretely, restore **MUST rebuild** the
  compartment(s) and the stack from the snapshot — allocating and repopulating them — not merely
  reassign the current state's name onto the compartment the fresh instance was constructed with
  (which would leave a compartment labelled one state while holding another state's variables).
- **Schema check** — a snapshot whose [manifest](../glossary.md#manifest) (its type-shape
  fingerprint — which states carry which typed state variables and args, and which domain fields
  have which types) does not match the running program **MUST** be refused with a diagnostic,
  never silently mis-restored into a different shape. The fingerprint therefore covers compartment
  shape, not only the domain field list.

These four, plus the type-identity work below, are the **entirety** of framec's own persistence
code. Everything else is the serializer's job.

### The regimes — determined by the language, not by choice

Whether framec must supply type identity is a property of the target language, not a design
preference. This yields three [regimes](../glossary.md#regime), and every supported target falls
into exactly one.

- **Regime A — statically typed** (Rust, Go, Swift, C#, Kotlin, Java, Dart, C++, C). framec
  knows each field's type at generation time and hands it to the serializer, which deserializes
  **into that declared type**. The bytes are **pure data with no type tag**. A user value that
  happens to contain a marker-like key is inert — it is deserialized as whatever the declared
  type says. Type-mimicry restoration (the failure a prior design shipped, where a user
  container carrying a reserved type key was rebuilt as a typed instance) is therefore
  **impossible by construction** on this regime, and framec adds no framing to prevent it
  because none is needed. (A serializer may carry its *own* discriminant for a polymorphic
  field — serde's tagged enums, `System.Text.Json` polymorphism — but that tag is the
  serializer's, targeting the serializer's own types, not a framec-injected tag sharing a
  namespace with user data. framec still writes none.)

- **Regime B — dynamically typed and reflective** (Python, JavaScript/TypeScript, Ruby, PHP).
  framec has no compile-time type, and the target's plain serializer (e.g. `json`) will not, on
  its own, reconstruct a user-defined class. framec **MUST** therefore place the value's type
  identity **in the snapshot**, and it **MUST** do so [**out of band**](../glossary.md#out-of-band-framing)
  — in an envelope whose slots cannot collide with the user's own data — so a user container that
  merely contains the
  envelope's key names is never mistaken for a typed value. On this regime framec's own
  mechanism is real and required: the out-of-band envelope, save-time escaping of user data,
  and an **emitted closed-world registry** of the types the program defines.

- **Regime C — dynamically typed and non-reflective** (Lua, GDScript). The runtime cannot name
  a value's type on save or resolve a name on restore. A value that needs a reconstructed
  *type* is beyond what the language expresses; the faithful form is the native container, and
  needing more is a **reachability limit that MUST be reported**, never a silent erasure.

### The closed-world safety floor — Regime B only

On Regime B, restore reads a type name from the snapshot. It **MUST** resolve that name **only
against types the program itself defines** — the [closed-world](../glossary.md#closed-world)
set — never against ambient globals, imports, or the standard library. Visibility is not enough: a type merely reachable in the module namespace but
defined elsewhere (an import, a monkeypatched class) **MUST NOT** resolve. framec emits the
closed-world set as an explicit registry rather than discovering it by enumerating a module or
file. This floor is **non-deferrable** and ships with the reflective route.

### The out-of-band framing requirement — Regime B only

The out-of-band envelope is required **only where framec injects a type tag** — that is, only on
Regime B. On Regime A there is no tag in the bytes, so there is nothing to collide with and the
requirement is moot. A design that mandates the envelope universally is over-generalized; this
RFC scopes it to the regime that has the problem.

### The serializer, per target

Delegation names a concrete serializer for each target. Where the language provides one
in its standard library the choice is forced; where it does not, framec **MUST** pick one and
state it, so persistence has a single, documented mechanism per target rather than a bespoke one.

| Target | Regime | Serializer framec delegates to |
|---|---|---|
| Rust | A | `serde` + `serde_json` |
| Go | A | `encoding/json` (standard library) |
| Swift | A | `Codable` (standard library) |
| C# | A | `System.Text.Json` (standard library) |
| Dart | A | `dart:convert` (standard library) |
| Kotlin | A | `kotlinx.serialization` |
| Java | A | Jackson (or Gson) — a chosen dependency |
| C++ | A | a chosen JSON library (e.g. nlohmann/json) |
| **C** | A | cJSON + author-supplied `_persist_pack_field_<Type>` hooks for user types. See below |
| Python | B | `json` + framec envelope + registry |
| JavaScript / TypeScript | B | `JSON` + framec envelope + registry |
| Ruby | B | `json` + framec envelope + registry |
| PHP | B | `json` + framec envelope + registry |
| Lua | C | native tables; a needed *type* is a reachability limit |
| GDScript | C | Godot resource machinery |

**C is the one genuine exception.** C has no standard serializer and no de-facto one framec can
assume — and, lacking reflection, nothing in C can marshal a user `struct` automatically. So C
is where the delegation principle's escape clause applies: *framec builds its own mechanism only
to supply a capability the host lacks*, and here the missing capability — per-type marshalling —
is supplied by the **author**, not framec. **Decision: C uses a manual marshalling-hook
convention over a JSON library (cJSON).** For a scalar or string field framec marshals directly;
for a user-defined type, framec emits a call to an author-supplied pair by a fixed naming
convention — `<System>_persist_pack_field_<Type>(const void*) -> cJSON*` and
`<System>_persist_unpack_field_<Type>(cJSON*, void*)` — and the author defines them. This keeps
framec **type-ignorant** (it emits the hook call with no branch on the type; the author, who owns
the type, owns its marshalling — exactly Java `readObject`/`writeObject`, Go `MarshalJSON`, C++
`to_json`/`from_json`), and it restores parity with the shipping compiler and the corpus, which
already use this convention. A field whose type is neither a framec-marshalled scalar/string nor
accompanied by the hook pair is a **compile-time diagnostic**, not a silent miscompile.

## The snapshot — the persisted data structure

Two terms, kept distinct:

- The **snapshot** is the whole persisted value `save` returns and `load` consumes; its host type
  is set by `@@[persist(<blob_type>)]` (a `String`, a byte buffer, …). It carries the complete
  recoverable runtime state.
- The **[manifest](../glossary.md#manifest)** is *one field inside* the snapshot (`_schema`): a
  fingerprint of the type *shape*, carrying no state data, used only for drift detection (below).

### Envelope

The snapshot's top level holds:

- **`_compartment`** — the active [compartment](../glossary.md#compartment): the live per-state
  record, which recursively contains its HSM parent via `parent_compartment`.
- **`_stack`** — the ordered list of compartments pushed with `push$`/`pop$`, each a full
  compartment.
- **`_schema`** — the type-shape fingerprint (the manifest).
- **one member per persisted domain field**, keyed by name. A domain field that is itself a nested
  `@@system` is inlined as that child's own snapshot.

### Compartment (recursive)

Each compartment records the runtime data of one active state:

- `state` — the state name; the **routing key** for type-directed reconstruction.
- `state_vars` — the `$.` variables, keyed by name.
- `state_args` / `enter_args` / `exit_args` — the state, `$>`, and `$<` arguments.
- `parent_compartment` — the enclosing HSM compartment, or null at the root.

A user-typed state variable on a *pushed-and-persisted* compartment round-trips at the same
fidelity as a domain field — the full-compartment contract of § "What framec owns," made concrete.

### Value encoding — by regime

- Primitives and native collections serialise directly.
- **Regime A** (static): a user-typed value is **pure data, no tag**; its declared type drives
  reconstruction.
- **Regime B** (reflective): a user-typed value is wrapped in the **out-of-band envelope**
  `{"@f:t": "<Type>", "@f:v": {<fields>}}` — type identity in the disjoint `@f:t` slot, never
  beside the user's data (the #233 fix). Nested user types and collection elements each carry
  their own envelope and reconstruct recursively.
- **Regime C** (non-reflective): the author's marshalling hook supplies the encoding.

### Worked snapshot (illustrative)

A Regime B (Python) snapshot of a machine whose pushed `$Idle` compartment holds a user-typed
state var `$.sv: Vec2`, now active in `$Active` over an HSM parent `$Base`:

```json
{
  "_schema": "frame-persist:1|…fingerprint…",
  "_compartment": {
    "state": "Active", "state_vars": {}, "state_args": {}, "enter_args": {}, "exit_args": {},
    "parent_compartment": {
      "state": "Base", "state_vars": {}, "state_args": {}, "enter_args": {}, "exit_args": {},
      "parent_compartment": null
    }
  },
  "_stack": [
    {
      "state": "Idle",
      "state_vars": { "sv": { "@f:t": "Vec2", "@f:v": { "x": 3.0, "y": 4.0 } } },
      "state_args": {}, "enter_args": {}, "exit_args": {}, "parent_compartment": null
    }
  ],
  "marker": 1
}
```

The pushed `Idle` carries its live `Vec2` out-of-band; `marker` is a domain field; `_schema` is
the fingerprint, carrying no data.

### The manifest and drift protection

Every persisted field's declared type — **domain fields and, per state, state variables and
args** — is recorded once (the [manifest](../glossary.md#manifest); one derivation shared by every
backend) and serialised into `_schema` as an **order-insensitive, length-prefixed fingerprint**:
a format version, then per state (sorted by name) its typed state variables and arg types, then
the domain field types. It holds type *identity*, never values. Sort-then-fingerprint is the
standard *canonical-form-before-hash* discipline (cf. Avro's Parsing Canonical Form + CRC-64
fingerprint, Confluent Schema Registry ids). On restore, a fingerprint mismatch is **refused** as
drift (E751) — "same schema" is verified, not assumed. This is deliberately **stricter** than
Avro reader/writer resolution: equality-refuse gives *detection*, not *resolution*; migrating a
drifted snapshot is a deferred layer.

## Polymorphism

A field or state variable may be declared as a **base type but hold a subtype** at save. Faithful
restore must reconstruct the *concrete* runtime type, not the declared one.

- **Regime B handles this by construction.** The out-of-band envelope tags each value with its
  **runtime** type (`type(o)`), so a subtype in a base-typed slot is tagged with — and rebuilt
  as — the subtype. No extra work.
- **Regime A does not, by default.** The host serializer deserialises into the **declared** type,
  so a subtype in a base slot *loses* its concrete identity. Recovering it requires a
  **discriminator/tag** — serde tagged / `typetag` enums, Jackson `@JsonTypeInfo`,
  `System.Text.Json` polymorphism, a C tag. That discriminator must be the *serializer's* (its
  tag, its own types), **not** a framec tag in the user's namespace — which would re-introduce
  the #233 collision.
- **Security.** A concrete-type name in the bytes is attacker-controllable — polymorphic
  `TypeNameHandling` / gadget chains are a known CVE class — so the closed-world floor applies:
  resolve only against the program's own types.

**Scope.** Regime B polymorphism ships (it is inherent to the envelope). Regime A polymorphism —
a **declarative subtype mechanism lowered to each target's native discriminated serialization** —
is a **named deferred layer** (§ Deferred layers), not built. Until then a Regime A base-typed
slot is **declared-type fidelity**, and a fixture pins that so a green suite never implies subtype
recovery it does not do.

## Security is a property, not a driver

Persistence is not a security feature, and security is not a goal of this RFC — it is a property
the automated tier must **preserve**. Wherever a type name travels in the bytes it is
attacker-controllable, so restore resolves it **only** against the program's own types (a
**closed world** — the program's own module/compilation unit, never imports or ambient globals),
refuses a foreign name (**E750**), and rebuilds **without running the type's constructor**
(allocate-without-init). A hostile snapshot therefore cannot instantiate arbitrary types or run
initialisation code. This is the accepted mitigation for the deserialisation attack class — why
`BinaryFormatter` was withdrawn and polymorphic gadget chains are CVEs — and framec's allow-set is
*tighter* than the usual user-configured list: the program's own types, **identity-checked**, not
a name lookup against a namespace (which readmits imports — the Ruby-leak). It applies in **Regime
B** (and Regime C's author-supplied tags, resolved closed-world); **Regime A carries no framec tag
at all**. The residual, bounded blast radius is exactly what the field expects: attacker-controlled
*field values* written into a legitimate own-type object — never a foreign type, never code
execution. A snapshot is **untrusted input**. framec never inspects a user type's fields in any
regime — the [Oceans model](../glossary.md#oceans-model) holds; a type name is an opaque, verbatim
string throughout.

## Diagnostics — the persistence error codes

| code | raised when | when |
|---|---|---|
| **E814** | a `@@[persist]` system does not declare the `@@[save]`/`@@[load]` method names | compile |
| **E750** | restore cannot resolve a blob-named type against the program's own types (Regime B closed-world floor) | restore |
| **E751** | manifest/schema drift — the snapshot fingerprint does not match the running program | restore |
| **E700** | `save` attempted on a non-quiescent system (the run-to-completion invariant — a system mid-transition has no stable state to capture) | save |
| **C missing hook** | a C user-typed field/state-var with no author `_persist_pack_field_<Type>` pair | compile |

(The interim `E752` — "C refuses a user type" — is **withdrawn**: C now uses the author-hook
convention with a missing-hook diagnostic, not a blanket refusal.)

## Examples

A persistent system delegates entirely; the author writes ordinary Frame. Persistence uses the
established three-attribute stack — `@@[persist(<blob_type>)]` for the serialized form's type,
and `@@[save(<name>)]` / `@@[load(<name>)]` to *name* the generated save and load methods (bare
`@@[persist]` is rejected, **E814**):

```frame
@@[persist(str)]
@@[save(snapshot)]
@@[load(restore)]
@@system Counter {
    interface:
        bump()
    machine:
        $Counting {
            bump() { @@:self.n = @@:self.n + 1 }
        }
    domain:
        n: int = 0
}
```

On a Regime A target, framec generates the `snapshot()` and `restore()` pair the author named:
they carry the schema and control state and hand `n` — and any user-typed, nested, or collection
field — straight to the serializer. A persisted user-defined type **MUST** be serializable by the
host serializer (in Rust, it **MUST** derive `Serialize` / `Deserialize`); the serializer, not
framec, enforces this — the **self-marshalling requirement**.

```frame
// A user type in a persisted field round-trips because the serializer handles it,
// not because framec wrote any code about `Vec2`.
@@[persist(str)]
@@[save(snapshot)]
@@[load(restore)]
@@system Body {
    interface:
        step()
    machine:
        $Moving {
            step() { @@:self.pos = advance(@@:self.pos) }
        }
    domain:
        pos: Vec2 = origin()
}
```

On a Regime B target the same source produces the same-named save/load pair, which additionally
wraps each typed value in the out-of-band envelope and resolves types on restore only against the
program's own closed-world registry.

## Alternatives

- **A uniform, framec-owned format across every target.** Rejected. That is *cross-language
  portability*, a separate and much larger project than single-language round-trip, and it forces
  framec to re-implement — across seventeen targets — serialization the languages already do
  better. It is the ambition that produced the tail-chasing. If it is ever wanted, it is its own
  RFC, layered on top of this one, not a precondition of it.

- **A dependency-free, hand-rolled format.** Rejected. "No dependency" cannot coexist with
  "type-ignorant" and "faithful user types": to serialize a user type without a library, framec
  must generate code that inspects the type, which is exactly the per-type branching the
  type-ignorance boundary forbids. The dependency-free flat format could only ever do scalars,
  and did so by violating that boundary. "No dependency" was never an RFC requirement; it was an
  implementation impulse, and it is retired here.

- **One mechanism for all targets.** Rejected. Static and dynamic languages genuinely differ in
  whether the runtime can supply a value's type identity. Forcing a single mechanism means either
  carrying a type tag on static targets that do not need it (and re-introducing the collision
  problem it creates), or withholding it from dynamic targets that do. The regime split is
  not a hybrid of convenience; it is the shape of the problem.

- **Building our own serializer to beat the per-language libraries.** Rejected as infeasible and
  unnecessary. For a single language, the language's own serializer is the state of the art;
  framec's leverage is the Frame-specific frame around it, not the marshalling inside it.

## Migration

This RFC **supersedes** [RFC-0053](rfc-0053.md), [RFC-0054](rfc-0054.md), and
[RFC-0055](rfc-0055.md), and retires the cleanroom persistence roadmap. Those documents are
marked deprecated and **MUST NOT** be used as the basis for new work.

For existing cleanroom code: the Rust backend uses `serde`, the Java backend uses `Gson`, and the
Python backend keeps its out-of-band envelope + closed-world registry (the Regime B mechanism this
RFC blesses) — each marshals **domain-field values** faithfully, including user types, nesting,
and collections. Two corrections remain outstanding against the contract above, and are the
current persistence work: (1) **compartment + stack fidelity** — all four backends today persist
only the domain fields and the current state *name*, dropping state variables, args, and the
stack (a crash on `pop$`-after-restore, and mislabelled compartments); this **MUST** be fixed to
persist and rebuild the full compartment(s) and stack. (2) **C** must move from its interim
scalars-only refusal to the author-hook + cJSON convention above. No Frame source changes.

## Deferred layers

These are **named, not built** — recorded here so the sequence is explicit and none is lost in a
future rewrite (as full-compartment fidelity and polymorphism once were). Each is out of scope for
the contract above; each carries the open decision that gates it.

1. **Regime A polymorphism.** A subtype in a base-typed slot on a static target, recovered via the
   serializer's native discriminated serialization (serde tagged / `typetag`, Jackson
   `@JsonTypeInfo`, `System.Text.Json`, a C tag), driven by a **declarative subtype declaration**
   in Frame. Regime B already covers this via the runtime-tagged envelope. *Open:* the Frame
   surface for declaring a subtype set, and its lowering per target.

2. **Pathological shapes.** Reference cycles, shared object identity, and types with no reflectable
   field map (slot-based classes). A borrowed serializer cannot round-trip these even with
   reflection; the foundation targets acyclic values with a reflectable field map. *Open:* which
   to support and by what means (typically the owned format, below).

3. **Schema migration.** Drift today is *detected* and refused (E751, equality-refuse). Resolving a
   compatibly-evolved snapshot — add / remove / rename a field, à la Avro reader/writer resolution
   or Protobuf compatibility — is a separate effort. *Open:* the compatibility rules and their
   per-target mechanism.

4. **A portable, framec-owned wire format.** The encoding today is each target's serializer, so a
   snapshot is single-language (§ Scope). An owned format would enable cross-target restore,
   represent what borrowed libraries cannot (cycles, identity), and re-tighten load validation.
   Its own RFC. *Open:* the whole format.

5. **Untrusted-snapshot security, formalized.** Beyond the closed-world floor (which co-ships): an
   explicit, **identity-checked allow-set** built from the program's own type definitions, and the
   trust model for a snapshot originating outside the program. *Open:* the concrete per-target
   allow-set enforcement, and whether "restore instantiates nothing a snapshot names" is relaxed
   to the bounded own-type form or preserved by other means.

6. **Compile-time diagnosability.** Rejecting a program that cannot be persisted faithfully on the
   chosen target *before* it runs, rather than at restore. framec has no type system, so it cannot
   in general decide a value is non-reconstructable without the source-text oracle the compiler
   discipline forbids. *Open:* a deterministic **first-save** runtime error vs. requiring a **type
   annotation** on a class-valued persisted variable (decidable at build, at a small source cost).

7. **Regime-C surface + GDScript.** The author-hook convention (C's names / mangling) generalises
   to any Regime-C target that cannot reflect (Lua; GDScript if Godot's resource/reflection
   machinery does not satisfy Regime B). *Open:* GDScript's regime, and the hook surface for Lua.
