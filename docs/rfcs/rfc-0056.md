# RFC-0056 — Foundations

- **Status**: Draft (revision 2 — supersedes revision 1, which contained a material error; see §10)
- **Author**: Mark Truluck
- **Scope**: The foundational principles of a from-first-principles framec. Defines what the compiler
  *is* — its tree, its symbol table, its passes, and the rules that are **enforced** rather than
  encouraged.
- **Supersedes in spirit**: the "convert hand-rolled text oracles to FSMs" mandate. That mandate
  described a cleanup. This RFC describes an architecture in which the thing being cleaned up
  **cannot be written**.
- **Companions**: the Machine Family RFC (`@@efsm` and the certified strata — the recognizer side of
  this architecture); [RFC-0020](rfc-0020.md) (runtime reference architecture — the semantics to
  preserve); [RFC-0042](rfc-0042.md)/[RFC-0042.1](rfc-0042-1.md) (`@@fsm`; **0042.1 is Accepted and
  implemented** — it gives a recognizer a borrowed, positioned input source);
  [frame_machine_architecture.md](../frame_machine_architecture.md).

---

## 1. Summary

framec is rebuilt as a real compiler: a **lossless tree in which Frame constructs and native code are
sibling first-class nodes**, a symbol table with real name *and type* resolution, and passes that are
pure functions over that tree. Its recognizers are Frame machines whose **keyword is a machine-checked
certificate**. The rules that keep it honest are enforced by **types**, not by review.

---

## 2. Motivation

### 2.1 What actually went wrong

framec has been purged of hand-rolled text-scanning oracles **three times**. Each purge found the same
class of defect. A full census found **sixteen confirmed, shipped bugs, every one of them the same
mistake**:

> The compiler knows a fact while generating code, encodes that fact into **text**, throws the fact
> away, and then re-reads its own output — or the user's — to recover it.

They are not exotic. They are what happens when ordinary code meets a substring probe:

| The question the compiler asked the text | What broke |
|---|---|
| `contains("co_await")` | a *comment* mentioning `co_return` → the generated C++ **hangs forever** |
| `rfind(last non-whitespace)` | two ordinary assignments → **no semicolon** → fails to compile on **seven** targets |
| `contains("encoding/json")` | a *comment* mentioning it → the required import is suppressed |
| `windows(4) == "-> $"` | a *string literal* `"-> $A"` in a closure → **legal code rejected** |
| `starts_with("@@persist")` | a *docstring* mentioning it → **the build hard-fails** |
| `windows() == b"balance"` | a *string literal* → a PHP field silently takes the wrong value |
| `ends_with("Compartment")` | a user system named `LogCompartment` → **its factory silently vanishes** |

### 2.2 Why the purges failed

They were **cultural, not structural**. Each removed instances; none removed the *possibility*. Nothing
in the compiler's types prevented the next author — under deadline, at velocity — from writing
`code.contains("co_await")` again. So they did.

The anti-regression tool built to keep the audit "done" is itself a **grep** — the exact technique the
mandate forbids. On its last run it was **wrong about 76% of what it flagged and silent about every one
of the sixteen bugs**. It is a linter attempting a type-checker's job.

**A fourth purge would fail for the fourth time.** The defect is not in the instances. It is in an
architecture that permits them.

### 2.3 The root cause, precisely

**framec has no AST of handler bodies.** It has an AST of the system skeleton and, below that line, a
flat stream of segments with native code as an opaque `NativeBlock { code: String }`.

The consequence is visible in the node kinds themselves. Two of Frame's three assignment forms get a
statement-shaped node; the third gets nothing:

| Frame source | Node produced | Spans |
|---|---|---|
| `$.x = 1` | a state-var assignment | the whole statement |
| `@@:data.k = 1` | a context-data assignment | the whole statement |
| `@@:self.a = 1` | a *reference* to self | **only `@@:self`** — `.a = 1` falls out as untyped text |

Because the statement never exists, nothing can ask *"is it terminated?"* — so the compiler searches
its own emitted string for the last non-whitespace byte, and lands the semicolon **inside a comment**.
Every other bug in the table is the same shape.

And it is not confined to handler bodies. **There is no file-level tree either.** `ModuleAst` holds
systems only — an `@@fsm` declaration is *not in the module tree at all* — and a file's structure is
split across a `SourceMap`, a `ModuleAst`, and a loose `FsmDeclAst` list, stitched back together by the
**assembler**, walking segments and pasting text. That is why the assembler must grep its own output to
find the `package` clause. It is the same failure, one level up.

### 2.4 The conflation that caused it

Frame's **Oceans model** says native code passes through verbatim: framec never *interprets* it. That
is a promise about the *language*, and it is correct.

It was read as a licence to leave native code **unstructured**. That does not follow, and the
conflation is load-bearing:

> **Opaque ≠ undelimited.**

framec must not know what a native statement *means*. It must absolutely know where one *ends*. Because
it refused to delimit, it had to re-scan; because it re-scanned, it guessed; because it guessed, it
shipped silent miscompiles.

This has a name. Frame's Oceans model is an **island grammar** (Moonen, 2001): precise productions for
the *islands* you care about, a permissive catch-all for the *water*. But in an island grammar **the
water is still tokenized and delimited** — it is not a blob. framec adopted the idea and skipped the
part that makes it work.

---

## 3. Guide-level explanation

- **It is a real compiler.** A lossless tree, a symbol table with types, pure passes, spans on
  everything.
- **Native code is a first-class node, not a gap.** It is *held*, with known boundaries, and never read.
- **Its recognizers are certified machines.** The keyword names a machine class and the compiler
  refuses to let the name lie.
- **A fact is computed once and carried.** No pass re-derives what an earlier pass knew. Names are for
  humans; facts live on nodes.
- **The rules are types.** What must not be written, cannot be written.

---

## 4. The principles

RFC 2119 keywords (**MUST**, **MUST NOT**, **SHOULD**, **MAY**) are used with their standard meanings.

### P1 — A real compiler

1. **A lossless (full-fidelity) tree.** Every byte of the source **MUST** be covered by exactly one node
   — Frame construct, native statement, or trivia. The tree **MUST** satisfy the round-trip property:

   > **`unparse(parse(src)) == src`, byte for byte.**

   This is a **property test**, not an example test, and it is brutal: you cannot forget a byte or
   quietly widen a span. It is distinct from codegen, which is a *different* fold (tree → target text).
   *(Prior art: Roslyn red-green trees; rust-analyzer's `rowan`; tree-sitter.)*

2. **One tree per file, islands and water as siblings.**

   ```rust
   struct FileAst { items: Vec<Item> }     // total over the file
   enum Item { Native(NativeSpan), Pragma(..), System(SystemAst), Fsm(FsmDeclAst) }

   enum Stmt { Native(NativeStmt), Transition(..), StateVarAssign(..), ContextData(..), … }
   struct NativeStmt { span: Span, terminated: bool, block_depth: u32 }   // content NEVER read
   ```

   Recursively total: a handler body is *not* one native blob but an ordered list in which every byte —
   **including trivia** — belongs to exactly one statement.

   An `@@efsm` declaration is a **sibling item in the file tree**, while the *efsm compiler* remains a
   separate crate consuming `FsmDeclAst`. One file tree, separate compilers per island type. (The
   Vue-SFC / tree-sitter-injection shape.)

3. **A symbol table with type resolution**, not merely names. It **MUST** resolve a domain field's
   declared type to a system when that type names one. Today five sites hand-tokenize type text and a
   *validator* reaches into the *code generator* to ask what systems exist.

4. **Spans on every node, from the first commit.** Source maps, the AST dump, the symbol export, and
   real diagnostics all fall out of one field. Retrofit them and you build a second span mechanism.

5. **Passes are pure functions over immutable inputs.** No pass **MAY** mutate an earlier pass's output,
   and **no pass MAY reconcile two views of the same source by positional index-pairing.** framec
   currently staples the parser's tree to the scanner's regions by *counting*, and the two have already
   diverged — one recognizes 21 Frame forms, the other 6.

### P2 — Machines all the way down (with teeth)

Every recognizer, scanner, classifier, and mode-driven pass **MUST** be a Frame machine. framec is
Frame's flagship user.

**This needs teeth, because we have already "done" it and got costumes.** framec contains ~30 artifacts
that look like machines and are not. **Judge by where the *mode* lives — never by whether a native loop
exists.** A native *cursor-advance* loop inside one mode is fine; every genuine `BodyCloser` has one.

- **The vtable shell.** `$Init` + one state per interface method; transitions only ever *out* of
  `$Init`. The "states" are **method names**; the mode is a **native local** (`in_string: u8`) inside a
  `while` loop that *is* the real machine. All 15 `SyntaxSkipper`s.
- **The sequencer shell.** Real states, real transitions, **zero** native loops — and still not a
  machine: the "states" are **pass names** in a fixed order, and nothing depends on accumulated input
  history. (`fsm_validator.frs`, `pipeline_supervisor.frs`.) A strict "everything is a machine" reading
  would **mass-produce** these.
- **The tarpit.** One state holding a 250-line native body. And its cousin, a table lookup in machine
  form: `is_dynamic_target.frs` had to encode a `bool` as the **string `"true"`**, and its own header
  records the ergonomic damage.

**The criterion (normative).** A pass is a **machine** iff **(a)** its behavior depends on *accumulated
input history* — the same input means different things depending on what preceded it — **and (b)** that
history quotients into a *finite, nameable* set of modes.

- (a) fails → it is a **function**. Say so.
- (a) and (b) hold → a **Frame machine**, and the **mode MUST be a Frame state, never a native local.**
  The cursor advance **MAY** be native.
- (a) holds, (b) fails (the mode is unbounded or tree-shaped) → a **parser**, not a machine.

### P3 — The keyword is a certificate

A machine construct's keyword **MUST** name a machine class the compiler **verifies**. It **MUST NOT**
be possible to write a program whose keyword lies about its power.

This is not hypothetical. **The construct shipped as `@@fsm` is Turing-complete**: two action-written
counters, a `when` guard branching on zero, and a non-consuming (ε) cycle compile clean today — a
two-counter Minsky machine — while the spec says *"regular-language only; the runtime is a DFA
executor."* The livelock hazard the spec documents as a footnote **is the ε-edge that completes the
embedding**; they are the same fact.

Therefore (per the Machine Family RFC): the honest language is **`@@efsm`**, and stronger names are
**minted downward by adding validators, not runtimes** — `@@fsm` (certified DFA, decidable
equivalence), `@@pda` (visibly pushdown), `@@rfsm` (registers).

**Choose the weakest machine that works — and know what "works" means.** Bounding an unbounded counter
does **not** approximate a nesting scanner; it **changes the language it recognizes**, so a saturating
`int(0..K)` silently mis-scans past depth K. Balanced nesting to unbounded depth is *provably not
regular*: those scanners are `@@pda`-class, or they stay `@@efsm`. **A certificate that requires
changing the accepted language is not a certificate — it is a bug.**

**Progress is separable and MUST be the default.** Requiring every transition cycle to consume ≥1 input
element buys **termination** (≤ O(n) steps ⇒ *not* Turing-complete) *independently* of the
finite-guard strip. framec's own scanners run **inside the compiler**: an uncertified machine that
spins **hangs framec on a source file**. Every framec-internal scanner **MUST** carry progress,
whatever stratum it ends at.

### P4 — The delimitation contract (opaque ≠ undelimited)

1. framec **MUST NOT** interpret native code — not its expressions, not its types, not its spelling.
2. framec **MUST** delimit native code: where each native statement begins and ends, whether it is
   terminated, its block depth.
3. Delimitation **MUST** be performed by a per-target machine (P2, P3), **exactly once**, in the front
   end (P6).
4. **There are no exceptions.** Revision 1 of this RFC carved one out for lowering a user's `if`/`else`
   in a Lua handler body. That exception was **wrong**: `if COND { }` is **framec's own undeclared
   syntax** — the Lua fixture corpus never writes `then` even once, and the identical source emits
   *invalid* Python, JS, Ruby and GDScript. `block_transform` was not interpreting foreign code; it was
   **re-deriving framec's own construct from text framec emitted** — this RFC's root cause, in the one
   place it was exempted. `if`/`while` are **not** Frame constructs (the `@@system` parser has no such
   keyword and never did). **A Lua body contains Lua.** `block_transform` and both output-block machines
   are **deleted**, and with them the entire class of bug they shipped.

### P5 — Illegal states unrepresentable: enforce with types, not review

1. **A pass MAY interrogate a node about facts *framec* put there. It MUST NEVER interrogate a node
   about facts the *user* put there.** Every predicate over native text is an oracle **by
   construction** — the compiler's own design says it does not understand that text. **Every such
   predicate found in the census was a confirmed bug.** That is not a correlation; it is the rule being
   sound.
2. Emitted text and native text **MUST** be distinct types whose APIs **do not expose** `contains`,
   `find`, `rfind`, `starts_with`, `ends_with`, `split`, or `replace`. The compiler literally **cannot**
   ask text a structural question.
3. The one legitimate place framec reads text it never parsed — the delimiting scanners of P4 — **MUST**
   be the only place those types can be opened, through a single named boundary.
4. Facts **MUST** be carried on nodes and **MUST NOT** be encoded in generated names. A method's *name*
   (`_s_`, `__kernel`, `save_state`) is today the ad-hoc wire format of a missing role field, decoded by
   two independent passes with two *different* prefix tables. **Names are for humans. Tags are for
   compilers.**
5. **Grep-based ratchets MUST NOT be used to enforce any rule in this RFC.** A rule that can only be
   checked by grep is not enforced; it is hoped for. The replacement is the **classifier** — built from
   the same checkers the validator runs, so it cannot drift from what it checks.

### P6 — Emission is one-way

> **Once a node has been rendered to text, NO pass MAY run over that text.** Codegen is a fold from IR
> to string; the string is terminal. **There are no post-emission passes.**

**This is not implied by P5, and that is the trap.** The post-emission family mostly does not call
`contains`: one uses `.lines()` + `.join()`; another `.lines()` + `.min()`; `block_transform` runs a
*perfectly principled dogfooded lexer* over framec's own output; the casing pass does a name
substitution. **Every one is an oracle, and every one survives P5.** A pass that tokenizes framec's own
output with an impeccable machine is still re-deriving structure framec threw away.

P6 kills, as one class, **roughly half of the sixteen bugs**: the statement terminator, the C++
coroutine hang, the import injection, the Java unreachable-strip, the `await` rewrite, the PHP variable
prefixer, the block transform, and the casing rename.

### P7 — One fact, one computation

1. framec **MUST** have exactly **one** recognizer of the Frame grammar. It currently has two, over the
   same bytes, reconciled by counting — and they have diverged (21 forms vs 6).
2. A fact **MUST** be computed once, by the pass that owns it, and carried. No downstream pass **MAY**
   re-derive it — not from source, and above all not from emitted output.
3. **Code generation MUST NOT receive the source bytes.** The single parameter that hands the raw file
   to the generator is the mechanism of this entire bug class; the generator then re-runs the scanner and
   rebuilds a statement list the parser already built — *and which is already sitting in the symbol
   table, populated and unread.*
4. There **MUST** be one authority for the Frame grammar. Two recognizers exist because there was no
   single place the grammar was written down.

### P8 — framec terminates only what it emits

Frame statements (`-> $State`, `$.x = e`, `@@:data.k = e`, `@@:return = e`, `@@:(e)`) are framec's — it
emits them whole and **MUST** terminate them. **Everything else is the user's**, including
`@@:self.a = 1`, which is a *native assignment* with a Frame reference spliced into it (`@@:self` is a
read-only reference, not a mutation). framec **MUST NOT** add, remove, or move a native statement's
terminator.

The decisive argument is portability: if framec owned native terminators it would need per-target
terminator policy for 17 languages — and **Go has automatic semicolon insertion, where adding one is
actively wrong**; Lua and Python have none at all. Owning only what it emits, framec needs to know
**nothing** about the target's punctuation.

`terminated` on a native node (P1.2) is therefore an **observation** the compiler records — useful for
suppressing unreachable code — never an *edit* it makes.

### P9 — A machine must be able to scan input it does not own

**No author may be forced to choose between a real machine and an acceptable cost.** They will choose
cost, the mode will go into a native local, and the costumes come back — *rationally*.

This is not a hypothesis; it is the causal chain behind every bug in §2.1:

> `@@system`'s domain field must **own** its input → a full buffer copy on **every probe call** (71
> sites) → **O(n²)** → so the scan logic was hand-rolled into native loops → so the mode landed in
> **native locals** → **which is the string-blindness bug family.**

**The performance limitation produced the correctness bugs.**

The remedy exists and **MUST** be universal: an **input-source abstraction** — an *indexed accessor*
(`get(i)`, `len()`), not a borrow concept — plus a deferred, positioned drive (`over(src)`,
`scan_at(start)`). RFC-0042.1 already ships it for `@@fsm` **on Rust**; it **MUST** be extended to all
17 targets and to `@@system`. It is portable by construction: a no-op in GC targets, `ptr + len` in C, a
generic type parameter in Rust (whose lifetime rides *inside* the parameter, so Frame needs no lifetime
syntax and no type system).

### P10 — Outputs are first-class

Two artifacts, two contracts, **one walker** (a second walker drifts — framec already carries three
divergent literal emitters and a read/write pair that disagree):

1. **`--emit-symbols`** — a portable symbol index. A **public interface**: versioned schema, stable
   identifiers, additive evolution. Informed by SCIP / LSIF / LSP rather than invented. It unblocks
   cross-file `@@import` validation, which [RFC-0040](rfc-0040.md) defers *for exactly this reason*.
2. **`--dump-ast`** — a human-readable AST dump. Explicitly **unstable**. Its real value is as a **test
   oracle**: today the only way to see what framec *understood* is to read emitted target code, which is
   why all sixteen bugs hid — the misunderstanding and its symptom are three stages and a foreign
   toolchain apart. *Not required in the first release; the tree and its spans **MUST** be designed so it
   is cheap to add.*
3. **Diagnostics MUST carry spans** and **MUST NOT** be produced by a text probe. Four of the sixteen
   bugs are *false diagnostics* — valid Frame rejected — emitted by a comma counter that cannot see
   brackets or strings.

### P11 — Target knowledge is data where it can be

Where a per-target decision is a *table* — the statement terminator, the receiver spelling, the reserved
word set, the zero literal for a type — it **MUST** be a table with a single source. The census found
**five** duplicate zero-literal tables and **three** divergent literal emitters that disagree with one
another. Duplication across seventeen arms is not a style problem; it is a drift generator.

### P12 — Deprecation is deletion

A deprecated target **MUST** be deleted, not carried. Erlang is deprecated and still costs ~10,000 lines
and a match arm in **thirty-three unrelated files — fourteen of them in exactly the code this rebuild
touches**. It **MUST NOT** be ported.

### P13 — The corpus is the specification

The rebuild is anchored by the existing corpus, and this is what makes it survivable: **6,141 fixtures
across 17 real toolchains, 240 snapshots, 1,587 unit tests, 54 RFCs, and a cross-language behavioural
trace-diff harness.** The semantics — the runtime, the persist contract, the async gate, seventeen
languages' hard-won corner cases — are **externalized and executable**, not folklore in the code. They
**MUST** be carried forward, not re-derived.

1. framec **MUST** be deterministic: identical input ⇒ byte-identical output. *(Verified: 120 paired
   runs, zero variance.)* Under a behaviour-preserving change **the correct diff is EMPTY** — every
   differing byte is a bug, adjudicated by a machine.
2. **Adversarial fixtures MUST land before any baseline is frozen.** This is a prerequisite, not a
   follow-up. **The current corpus bakes the bug in** — a canonical fixture *hand-writes* the semicolon
   framec should emit. Freezing byte-identity against it would freeze the defect into the specification.
   Every one of the sixteen bugs is a hostile-but-legal string or comment in an ordinary place; that is
   a **generated fuzz axis**, not a hand-written list.
3. Honest limit: those 6,141 fixtures caught **zero** of the sixteen bugs. Byte-identity proves the new
   front end is *not different*; it cannot prove it is *right*. That is exactly the property a strangler
   wants: **prove equivalence, then break equivalence deliberately, one fix at a time.** The adversarial
   fixtures are what prove rightness.

## 5. Drawbacks

- **P5's newtypes are viral.** Removing `contains` from the text types will be felt on every line that
  touches text. That friction is the point, and it will still be resented.
- **P2 can still be gamed.** The criterion is sharper than a loop-count rule, but "is this accumulated
  history?" is a judgment. The three named costumes are the current known evasions; expect a fourth.
- **P9 is language work.** Universalizing the input source across 17 targets is real effort before the
  compiler benefits. The alternative is doing the whole rebuild and getting the costumes back.
- **P13 is a discipline, not a mechanism.** Nothing forces anyone to write the adversarial fixture
  *before* the baseline. If we skip it, we freeze the bug in and this document becomes decoration.

## 6. Alternatives considered

- **A fourth purge.** Rejected: three have failed identically. Each removed instances; none removed the
  possibility.
- **Cut the seam only** (delete the source-bytes parameter, add a body AST, keep everything else).
  Genuinely cheaper, keeps the compiler shippable throughout, fixes the same bugs. Rejected on
  **process** grounds, not technical ones: it leaves the post-emission family alive, and this codebase's
  demonstrated failure mode is that a surviving pattern regrows. **If the rebuild stalls, this is the
  fallback.**
- **A total rewrite** (new compiler, port the backends). Rejected: more than half the codebase — the 17
  backends, the efsm codegen, machinery, runtime, persist, graphviz — **never opens a source byte** and
  would be copied verbatim. Option A's only genuinely new code is this plan's code, and a rewrite
  discards the byte-diff oracle at exactly the moment it is most needed.
- **A new pushdown construct beyond `@@pda`.** Not needed: `push$`/`pop$` already is a genuine pushdown
  mechanism, and nothing in the census required a free stack.

## 7. Migration

The Frame **language** is unchanged except for the additive work in P9, the `@@fsm` → `@@efsm` rename
(P3), and P8. Two migrations ship with codemods and diagnostics, not silently:

1. **P8** — sources that omit `;` in braced targets and compile *today only because the compiler adds
   one* will break.
2. **P4.4** — the Lua corpus writes `if COND { }` and must be migrated to real Lua (`if … then … end`).

The observable contract is the emitted code, and P13 makes it executable: **the new compiler must pass
the existing corpus.**

## 8. Unresolved questions

1. **What is the compilation unit?** A file? A module? The symbol table's scope, `@@import` resolution,
   and cross-file validation hang on this. Design against the **composition** cases (a system holding
   another system; cross-file import) — the single-file case will mislead.
2. **Phases or queries?** A strict pipeline is simpler; a demand-driven model (Salsa, rustc) is what an
   incremental/LSP future will want. Deciding late is expensive.
3. **`@@pda` timing.** The classifier audit decides it. Expect it to pull forward (P3).
4. **Saturation diagnostics.** If `int(lo..hi)` ships, saturation **must** emit a runtime diagnostic —
   otherwise it is a silent-wrong-answer machine. (An emit is not a branch, so it does not reopen the
   value→control channel.)
5. **How is P5 enforced across the FFI/WASM boundary**, where text becomes `String` again?

## 10. Changes from revision 1

Recorded because the error was material and the correction is the point of the document.

- **The old P7 ("Frame cannot express a scanner; this MUST be cleared first") was FALSE and is struck.**
  RFC-0042.1 is **Accepted and implemented**: `over()`, `scan_at()`, and `impl <Name>Input for &[u8]`
  ship, and framec's own leaf scanners already drive them zero-copy. The real gap was narrower and
  different — `@@system` cannot borrow, and the mechanism is Rust-only — and is now **P9**. The old P7
  also contradicted P7-new (P6/P7 of this revision): if you scan once and carry the stream, the
  "positioned probe called thousands of times" *ceases to exist*.
- **P2's rule is recast.** The old rule ("no unbounded native scan loop in a handler") **disqualified
  the `BodyCloser`s it held up as exemplary** and under-bit the tarpits. The criterion is now *where the
  mode lives*, plus the accumulated-history test.
- **P6 (emission is one-way) is added.** It was missing, it is not implied by P5, and it kills ~half the
  bugs as one class.
- **The Lua exception (old P4.4) is deleted.** It was framec's own construct, not foreign code. There
  are now **no** exceptions to P4.1.
- **P3 (the certificate doctrine) is added**, and the power taxonomy is corrected: the shipped `@@fsm` is
  **Turing-complete** (demonstrated), so the tiering could not rest on "`@@fsm` = regular."
- **P8 (who owns the terminator) is settled**, and the earlier claim that the canonical corpus "bakes in
  a workaround" is retracted: **the corpus was right; the auto-terminator was the bug.**
