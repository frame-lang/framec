# RFC-0054: Persistence type manifest — one algorithm for preserving and reviving types

- **Status:** Draft — 2026-07-09
- **Author:** Mark Truluck <mark.truluck@cogiton.com>
- **Created:** 2026-07-09
- **Builds on:** RFC-0053 (faithful persistence — the foundational round-trip contract; this RFC is the *how*, phased)

## Summary

RFC-0053 established the requirement: a saved system, restored, must reproduce
its state **faithfully** in every target — including user-typed values held not
just in domain fields but in *compartment* slots (state vars, state args, enter
args). Delivering that today means **eight independently hand-written
type-preservation implementations**, one per schema backend, plus a separate
reflective scheme for the dynamic-JSON backends. That divergence is a defect
factory: bringing compartment **state-var** fidelity up to the domain-field bar
required a distinct bug fix in *every* schema backend (go/java/kotlin restored a
user type as an untyped map; C# had three separate faults; swift crashed on
save; dart returned a plain Map; C truncated a struct into a `void*`), and a
trained review still found gaps in the plan for the last one.

This RFC replaces the ad-hoc duplication with a **single manifest** — a
structured, framec-derived description of *what type occupies each persisted
slot* — and delivers it in three deliberately separated phases:

- **Phase A — Codegen manifest (this RFC, implement now).** framec derives one
  `PersistManifest` from the machine AST and *every* backend's save/restore
  emission is generated from it. Compile-time only; no wire-format change; no
  new security surface. The per-backend per-state `switch` stops being
  hand-written and becomes a manifest walk. Fix/verify the algorithm once →
  correct on every backend by construction.
- **Phase B — Wire manifest (later; = RFC-0053 Layer 4).** Carry the manifest
  *in the snapshot* so the encoding is self-describing across languages: enables
  schema-evolution/migration and blob inspection. Re-opens the untrusted-input
  security surface for *every* backend, so it ships only behind the closed-world
  posture and its own decision.
- **Phase C — Portable revival (deep, later).** A language-neutral type identity
  so a snapshot saved by one target can be revived by another (e.g. a Python
  snapshot reconstructing a C struct). The most ambitious layer and the one most
  in tension with the Oceans model; explicitly out of scope until A and B land.

## Motivation

### Two strategies today, split by language capability

1. **Type-in-the-blob (reflective backends: python, ruby, php, js, ts, lua,
   gdscript).** Each serialized value carries a `__frame_type__` tag; restore
   resolves it against a *closed-world* registry (only types the program itself
   defines) and rebuilds without invoking the constructor. Self-describing,
   per value.
2. **Type-in-the-codegen (schema backends: rust, c#, java, kotlin, go, cpp,
   dart, swift, c).** The blob is pure data with no type info. framec knows the
   declared types at compile time and emits **per-state, per-name type-directed
   decode** — for the compartment's `state`, convert each slot back to its
   declared type. The "manifest" here is *implicit*: it lives as a hand-inlined
   `switch (state) { … }` re-written in every backend.

The reflective scheme is *already* a proto-manifest (a per-value one). The
schema scheme is a manifest smeared across eight code generators. Nothing names
or shares the underlying description, so the eight copies drift — and each drift
is a fidelity bug a user hits only when they put a user type in a state var.

### The concrete cost (2026-07 state-var sweep)

| Backend | The independently-written bug |
|---|---|
| go | state_vars `map[string]any` → JSON restores an object as a map → cast panics |
| java / kotlin | Jackson `LinkedHashMap` → cast throws |
| dart | `Map<String,dynamic>` → method call on a plain Map throws |
| c# | (1) read cast not parenthesised = compile error; (2) `object`-typed save = empty `{}`; (3) fields ignored without `IncludeFields` |
| swift | save drops a Codable value into `JSONSerialization` = `__SwiftValue` crash; restore untyped |
| c | struct crammed into `void*` = compile error; read cast to `int`; runtime deep-copy hardcodes `sizeof(double)` |
| rust / cpp | already correct (typed StateContext / `std::any` + typed restore) |

Every row is the *same* logical operation — "decode each compartment slot to its
declared type per the current state" — implemented, and mis-implemented, eight
times. That is the problem a manifest exists to end.

## The manifest

A `PersistManifest` is the single structured answer to "what type is each
persisted slot," derived once from the machine AST:

```
PersistManifest {
    // per state, the typed compartment slots
    states: [ StateManifest {
        name,
        state_vars:  [ (name, Type) ],   // keyed by name  (compartment.state_vars)
        state_args:  [ Type ],           // keyed by index (compartment.state_args)
        enter_args:  [ Type ],           // keyed by index (compartment.enter_args)
        exit_args:   [ Type ],           // keyed by index (compartment.exit_args)
    } ],
    domain: [ (field, Type) ],           // domain fields
}
```

`Type` is what framec already carries: an **opaque, verbatim type string** (the
type-ignorant boundary from RFC-0053 holds — framec never inspects a user type's
fields). The manifest describes *placement and identity strings*, not structure.
Restoration remains a per-backend *interpretation* of the manifest (each maps the
type string to its own decode primitive) — but it interprets **one** description
instead of re-deriving it eight times.

Both existing strategies become interpreters of the same manifest:
- reflective: emit the tag from, and resolve it against, the manifest;
- schema: generate the per-state decode *from* the manifest.

## Phase A — Codegen manifest (implement now)

### Scope

- Introduce `PersistManifest` (a Rust type in the codegen layer) built once per
  system from the `MachineAst` + domain, with a single builder.
- Route **every** backend's persist save/restore emission through it. The
  hand-inlined per-state `switch`/`when`/`match` blocks in
  `interface_gen/persist/<lang>.rs` are regenerated from the manifest by a shared
  driver that each backend parameterises with its own primitives (how it reads a
  slot, how it decodes a value of a declared type, how it stores it back).
- **No wire-format change.** Snapshots are byte-for-byte identical to today's
  (post-fix) output; this is a refactor that unifies emission, not a new format.
- **No new security surface.** Types stay fixed at codegen; schema backends
  remain closed-world by construction; reflective backends keep their existing
  registry.

### Design

The per-backend divergence is not in *what* to do (walk the manifest, decode
each slot to its declared type, keyed by the compartment's `state`) but in the
handful of language primitives it bottoms out in. Factor exactly those:

```
trait PersistCodegen {          // one impl per backend (or a small data table)
    fn read_slot(slot) -> expr;                 // how to read state_vars["k"] / args[i]
    fn decode_to(raw, ty: &str) -> stmt/expr;   // decode a raw value into declared `ty`
    fn store_slot(slot, decoded) -> stmt;        // write it back (owned/box/etc.)
    fn tag_on_save(value, ty) -> ...;            // reflective only; no-op for schema
}
```

A shared `emit_restore_from_manifest(manifest, &backend)` walks the manifest and
emits the per-state blocks uniformly. The nine string-templated `switch` bodies
collapse into one algorithm plus nine small primitive sets. The C-specific
concerns from the recent fix (heap-boxing a struct, `sizeof(T)` for the owned
deep-copy, the `_field_` helper reuse) become the C impl's `decode_to`/
`store_slot` — expressed once, not entangled with the walk.

### Compatibility & verification

- **Golden output:** the manifest-driven emitter must produce **byte-identical**
  snapshots to the current (post-2026-07-fix) per-backend output — the in-tree
  `<lang>_snapshots` suites are the gate (zero re-bless expected, or a reviewed,
  explained diff).
- **Fidelity:** the `persist_fidelity_state_var.*` + `persist_fidelity_value_type.*`
  suites (all backends) stay green on the 17-language matrix.
- **Single source:** a bug in the algorithm is now one fix; a new backend
  implements one primitive set, not a fresh copy of the switch.

### Non-goals for Phase A

- Not changing the wire format (Phase B).
- Not unifying type *identity* across languages (Phase C).
- Not lifting the separate, pre-existing `push$`/`pop$` compartment-restore
  defect (state vars not preserved across a modal push/pop, all types, all
  builds) — tracked independently; orthogonal to persistence.

## Phase B — Wire manifest (later; RFC-0053 Layer 4)

Carry the manifest in the snapshot (a header describing the compartment type
shape). Makes the format self-describing and portable-for-inspection, and is the
substrate for **schema evolution**: a restore can compare the saved manifest to
the program's current manifest and diagnose or migrate drift, instead of
silently mis-decoding. Costs: wire size, and — because the blob now *names
types* for every backend — it re-opens the untrusted-input attack surface that
only the reflective backends face today. Ships only behind the closed-world
resolution posture (own-module types via identity-checked allow-set, refuse
foreign with E750) generalised to all backends, and behind its own decision on
diagnosis (first-load runtime vs required annotation). Gated on Phase A.

## Phase C — Portable revival (deep; later)

A **language-neutral type identity** so a value saved under one target can be
revived under another — a Python snapshot reconstructing a C `struct Vec2`. This
requires a canonical cross-language identity + field mapping for user types,
which framec does not have and which is in direct tension with the Oceans model
(user types pass through *verbatim*, framec never models their fields). It is the
most valuable long-horizon capability (true portability of persisted state) and
the least constrained by current architecture. Explicitly deferred until A ships
and B is decided; called out here so the manifest in A/B is shaped with C in
mind (the manifest is the natural place a portable identity would later live).

## Relationship to RFC-0053

RFC-0053 is the *contract* (faithful round-trip, layered). RFC-0054 is the
*mechanism*, phased so the safe, high-value unification (A) lands immediately and
the format/portability ambitions (B/C) remain deliberate, separately-decided
layers — exactly the "fix the base first, add constraints deliberately"
discipline RFC-0053 set. Phase B **is** RFC-0053's deferred Layer 4; Phase A is
the refactor that makes every RFC-0053 backend a reader of one description
instead of a re-implementation of the same idea.

## Decision

Adopt the three-phase structure. **Implement Phase A now**, across all languages,
as a byte-identical refactor gated by the existing snapshot + fidelity suites.
Treat B and C as separate, later RFCs/decisions built on the manifest A
introduces.
